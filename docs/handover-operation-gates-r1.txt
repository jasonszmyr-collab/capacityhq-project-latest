Implementation
New service-only AUTO and authenticated-user operation RPCs acquire the same device/control lock, reject frozen state or stale expected generation, and return the current generation. User identity comes from auth.uid(); viewer command access remains allowed and setup requires admin. No acting-user identifier is accepted from the caller. AUTO RPC execution is denied to app/anonymous roles.

Confirmation RPC execution is revoked from authenticated users by default. The disposable test explicitly verifies that default, then grants it only inside its isolated database to exercise transitions. Production activation will require a separate reviewed grant after the full workflow is ready.

The backend enables the new paths only when HANDOVER_GATES_ENABLED is exactly true. Default remains disabled. Enabled paths authorize before non-STOP command enqueue and again at delivery, including AUTO and the legacy command API. Queued actor metadata retains its original generation; missing/stale generations are never silently upgraded. Definite gate/access refusal cancels pending delivery, while authorization outages preserve retry. STOP remains deliverable during gate freeze/outage. A delayed enqueue grant cannot overwrite a newer queued command, including a STOP already delivered during the wait.

Phone setup similarly authorizes creation and retains its generation, checks again at controller delivery, and gates retrieval of an OPEN session's credentials. Expired/replaced/rebooted sessions are rechecked after asynchronous authorization. Generation/access refusal discards the pending session; an outage withholds the packet and preserves retry. Old backend behavior remains covered with the feature flag disabled.

The integration creates C:\dev\HonorPole-OperationGateIntegration-R1-* from the clean committed share candidate. The draft migration includes consent/private gate state, the two gated share writers and the two operation RPCs. Acceptance boundaries
PostgreSQL data/accounts are synthetic, auth.uid() claims are synthetic, and native database roles/locks are real. HTTP/WebSocket transport is real localhost with all Supabase calls mocked. This is not live JWT, controller or ownership-finalization acceptance. Direct private-table generation changes in fixtures simulate the future finalizer; they are not a production release API.

Do not activate production confirmation or the feature flag yet. All serving instances must adopt compatible gates before confirmation can be exposed. In-flight responses issued before freeze and already delivered commands/setup packets still require the firmware quiescence barrier. The compiled recovery-rotation helper is not connected to such a barrier. STOP/queue drain, actual AP closure, recovery rotation, durable firmware inhibit, correlated device acknowledgement and release remain open.

Owner/recipient app/backend routes, membership/legacy/factory/account-deletion writer coordination, verified device evidence, final remove-all ownership transaction, generation increment, cancellation recovery/release, restart orchestration and live acceptance remain open. There is deliberately no ownership finalizer or gate-release RPC in this candidate.
